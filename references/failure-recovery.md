# AI 实验失败诊断与迭代

## 先区分失败类型

- **实现与协议问题**：代码、数据流、评估脚本、划分、预处理或比较条件有误；
- **数据与监督问题**：样本覆盖不足、噪声、长尾、采样偏差或监督信号不适合；
- **表征与结构问题**：所需信息未保留，容量、归纳偏置或信息流与任务不匹配；
- **目标与优化问题**：损失或奖励失配、梯度异常、训练不稳定或难以收敛；
- **推理与评估问题**：解码、后处理、分布偏移或评价协议影响结论；
- **资源与假设问题**：收益依赖当前项目缺少的预训练、数据或计算预算。

先排除实现和协议问题，再判断方法本身是否失败。用错误样本、训练曲线和消融寻找可区分的原因，不把单次结果直接归咎于模型结构。

## 分支处理

用户明确表示方法效果不佳时，可以在满足 Git 分支规则的情况下删除本地失败分支并回到父分支。若当前失败改动尚未提交且全部属于当前任务，可以回退这些改动；若包含其他任务改动，先询问。

如果用户认为方法有效，下一项方法改进从当前方法分支建立新的短命名分支，例如：

```text
feature/hard-mining__from_adaptive-loss
```

如果用户只要求路径、超参数、数据集、多 GPU 或其他工程适配，继续在当前分支处理，并说明是否值得同步到历史分支。

## 失败记录

删除分支引用前保留实验输出、日志、checkpoint、配置和失败原因。最终报告说明尝试了什么、实际观察、排除的原因、继续或停止的依据，以及下一步最小验证实验。
