# 失败恢复与迭代

## 先区分失败类型

- **实现失败**：代码错误、数据流错误、NaN、梯度异常或评估脚本错误；
- **实验协议失败**：数据划分、预处理、随机种子、资源条件或比较协议不一致；
- **方法失败**：实现和协议可靠，但核心指标没有改善或出现稳定退化；
- **假设不足**：方法需要额外条件、数据或模型容量，当前项目不满足。

先修复实现和协议问题，再判断方法本身是否应废弃。

## 分支处理

用户明确表示方法效果不佳时，可以在满足 Git 分支规则的情况下删除本地失败分支并回到父分支。若当前失败改动尚未提交且全部属于当前任务，可以回退这些改动；若包含其他任务改动，先询问。

如果用户认为方法有效，下一项方法改进从当前方法分支建立新的短命名分支，例如：

```text
feature/hard-mining__from_adaptive-loss
```

如果用户只要求路径、超参数、数据集、多 GPU 或其他工程适配，继续在当前分支处理，并说明是否值得同步到历史分支。

## 失败记录

删除分支引用前保留实验输出、日志、checkpoint、配置和失败原因。最终报告应说明：尝试了什么、观察到什么、排除了哪些实现问题、为什么继续或停止，以及下一步最小验证是什么。
